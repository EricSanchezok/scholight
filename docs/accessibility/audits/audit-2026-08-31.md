# Scholight accessibility and maintainability audit

Date: 2026-08-31

## Scope

The public and authentication surfaces were checked at desktop (1280 × 800) and mobile
(390 × 844) viewports:

- \`/\`
- \`/login\`
- \`/register\`
- \`/forgot-password\`
- \`/docs\`
- \`/search\`

The audit also reviewed the shared Identity avatar integration, mobile install flow,
service-worker behavior, route/style architecture, and the existing end-to-end suite.

## Automated results

- axe-core: 12 route/viewport combinations, 0 violations after remediation.
- \`npm run lint\`: passed with zero warnings.
- \`npm run typecheck\`: passed.
- \`npm run architecture:check\`: passed.
- \`npm run format:check\`: passed.
- Vitest: 31 files, 134 tests passed.
- Playwright E2E: 30 passed, 9 skipped; one existing timing-sensitive Markdown preview
  assertion was flaky on the first full run and passed on a focused repeat.
- Production build: passed. Vite still reports the existing main-chunk size advisory.

## Remediation

The code sample scroller now has a keyboard-focusable, labelled region so long examples
remain usable on mobile Safari and keyboard navigation. The form-muted token was darkened
slightly to meet the 4.5:1 contrast threshold.

Identity avatars remain read-only presentation data. Signed URLs refresh before expiry,
images use \`no-referrer\`, and initials remain the fallback when Identity has no avatar or
the image is unavailable.

Scholight now exposes a mobile-only install action. Android uses the native
\`beforeinstallprompt\` when available; iOS and in-app browsers receive manual guidance.
The manifest declares a stable id and scope, and the service worker is network-only with
an offline navigation message. It never caches account data, papers, or API responses.

## Dead-code and redundancy review

No confirmed dead production modules or redundant dependencies were found with the
repository's existing lint, type, architecture, test, and build checks. No package was
added just for static dead-code detection. The one accessibility helper introduced for
code scrolling is used by the docs code-block component and covered by the audit.
